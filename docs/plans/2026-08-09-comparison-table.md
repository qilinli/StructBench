# Provisional Results + Method-Comparison Table (ADR-0041 clause 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The results registry extends to per-(benchmark × method) with a `provisional` flag, and generated benchmark pages render a method-comparison table distinguishing blessed from provisional — v0.3's final agent-side deliverable, closing ADR-0041 clause 4 (and fixing the deforming_plate Quickstart's nonexistent-`cgn.toml` bug).

**Architecture:** Additive `provisional: bool = False` on `BaselineResult` (three existing blessed entries untouched); a `blessed_results` predicate + duplicate-family validation on `BenchmarkSpec` plus an explicit `quickstart_family` default; a new `_method_comparison` renderer (columns = methods, rows = split × metric, provisional tagging + footnote) added to both generated views; all committed pages regenerated once. ADR-0046 records the schema, the display-key contract for deforming_plate, and the pooled-number containment rule.

**Tech Stack:** Python 3.12, stdlib only (no new deps). Research basis: `scratch/2026-08-09-comparison-table-grounding.md` (workflow wf_7f62939a-0ae: 93 claims, 85 confirmed, 8 refuted-with-corrections — §-references below point there; note §6's corrections and the trailing controller note on c25).

## Global Constraints

- **Backward compatibility is absolute:** the THREE existing blessed entries (taylor cgn/7be9d4b, wave-1d cgn/48046ea, notch-impact cgn/5956d81 — grounding §2.3; there are three, not four) must keep reading as blessed with ZERO edits to their tuples. Achieved by `provisional: bool = False` appended after `notes` (all call sites are kwargs; trailing-default extension mirrors ADR-0037's `checkpoint_sha256` precedent, grounding §4.4).
- **Comparison statistic discipline:** the comparison table renders EVERY `metrics` key as a row — there is no "non-comparison metrics key" slot. Therefore ADR-0046 REFINES ADR-0043's Consequences ("`notes`/metrics") to **notes-only** for the MGN pooled blessing-gate aggregate: the pooled number lives in `notes` free-text, never a `metrics` key, BY CONVENTION (ADR-0046 states the refinement and the why; a dated pointer note on ADR-0043 records the narrowing — this is a deliberate tightening of 0043's letter, not silent drift).
- **Honest-not-silent (ADR-0033):** provisional tagging must be unmissable — column-header suffix ` (provisional)` plus a footnote line whenever any provisional column exists; the `" — private archive; publication parked"` marker (render.py:152-159) is the style precedent.
- **Renderer purity:** `render.py` functions stay pure over specs (no filesystem probing for configs); the Quickstart default family becomes explicit spec data.
- **No family-vocabulary validation** in `benchmarks.registry` — deliberately omitted, documented in ADR-0046. Rationale (corrected by plan review — there is NO import cycle; config's benchmarks import is function-local): YAGNI for a small maintainer-controlled vocabulary that `config.MODEL_FAMILIES` already governs at config-load time, and avoiding a new `benchmarks → config` coupling for a check that cannot fail in practice.
- **Drift tests govern, and every commit's FULL suite is green:** the section insertion changes the five `docs/benchmarks/*.md` pages (the index is byte-identical — `render_index` has no comparison section and no committed entry is provisional, so only `test_committed_benchmark_pages_are_up_to_date` is at stake, not the index drift test). The page-changing edit and the regeneration are ATOMIC (same commit, Task 3); Task 2 is deliberately output-neutral so it commits green. No test deselects, ever.
- **Branch:** all commits land on `feat/provisional-comparison-table` (ADR-0023 — `main` moves only on the maintainer's word).
- **Column/entry ordering:** RESULTS declaration order = comparison-column order (deterministic; convention documented in ADR-0046: blessed entries first — a convention, not validation).
- **Conventions:** ruff (88, E/F/I/UP/B), mypy strict, NumPy docstrings citing ADR-0033/0036/0041/0046, TDD, gates before every commit (`ruff format --check . && ruff check . && mypy src` + full `python -m pytest`). Known pre-existing failures NOT this plan's: ruff-format `notch_beam_2d_impact/__init__.py`; mypy `datasets/normalization.py`.

## Design decisions (closures of grounding §7 gaps — Task 4 turns these into ADR-0046)

| Gap | Decision |
|---|---|
| 1 | `provisional: bool = False`, appended after `notes` in `BaselineResult` (minimal, matches ADR-0041's literal "provisional flag"; enum is YAGNI for two states; default=False keeps existing entries blessed). |
| 2 | The comparison table is a NEW section (`## Method comparison`) added to BOTH generated views for EVERY benchmark, ADDITIVE to the existing per-result `## Numbers to beat` blocks (which keep the split-complete detail + checkpoint pointers unchanged). Single-method benchmarks get a one-column table — uniform, no renderer branch. All pages regenerate once. |
| 3 | Layout: columns = methods (`**family**` header, ≤3 today), rows = (split × metric) pairs. **Split axis:** iterate `spec.splits` in declaration order, include a split iff it appears in at least one result's metrics (exactly `_numbers_to_beat`'s existing rule; NO `eval_splits` involvement — review-corrected). **Metric-union order (first-seen rule, mirroring render.py's existing convention):** iterate results in declaration order, within each iterate its splits in card order, collect not-yet-seen metric keys into ONE global ordered list; per split-row-group, filter that list to keys present in ANY entry for that split, then stable-partition non-`qoi_` keys before `qoi_` keys. Missing cells `—`. Row label `split · metric`. This rule is what makes the Task 2 table pins deterministically constructible. |
| 4 | Provisional encoding: header suffix ` (provisional)` + one footnote when any provisional column exists: `*Provisional entries are best-effort implementations whose fidelity is not validated against published numbers (ADR-0044/0045) — never read them as blessed baselines.*` Blessed columns carry no tag. |
| 5 | Empty state: `*No results yet — method entries land here as runs are recorded (blessed or provisional).*` — deliberately distinct from `_numbers_to_beat`'s ADR-0033 "no official baseline yet" placeholder (this section is method-oriented and provisional entries land here too); ADR-0046 records the distinct-placeholder choice explicitly so it reads as a decision, not drift.
