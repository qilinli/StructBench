# Plan: `structbench-datagen card`, the last stage of ADR-0071

*Written 2026-11-18 before the work; approved by the maintainer and executed
the same day. One departure, in §3.5: the draws `feasible()` rejects are
counted by recomputing the plan with a counting hook, which the definition
alone determines, so neither a new `plan.json` nor a "not recorded" line was
needed. Also added while building: the provenance part says when runs were
launched through `--solver-args`, and `new` writes an empty card from the
template instead of copying the example's.*

*As first written: The stage is named in
ADR-0071 clause 1 and described in the design
(`2026-09-27-abaqus-datagen-platform-design.md`, "`card`"), so this is a plan
and not a record. Two things in it change public surface and are flag-first:
the template's `DATA_CARD.md` (markers and one section, §2) and a new stage
on the command (§1). The maintainer approves them by approving this plan; the
commits name them. The full suite is the gate.*

## What the stage is

    structbench-datagen card --dataset <dir> [--sweep <runs>/<name>] [--out FILE] [--check]

It renders the generated parts of `<dir>/DATA_CARD.md` from records and
leaves every other byte of the file as the author wrote it. It runs no
solver, reads no canonical case's arrays except through `qoi()` (§3, ranges),
and writes one file.

The rule it is built on, from the design: *renders from records only*. Each
generated part names the record it was read from and that record's sha256, or
says that the record does not exist. An absent record is stated, never left
blank (CORRECTIONS 2026-09-23): a card for a definition with no sweep is a
valid card that says what the definition declares and that nothing has run.

## 1. The stage

- `src/structbench/datagen/card.py`: pure section renderers
  (`record(s) -> str`), one per generated part, and `render_card(text,
  parts) -> str`, which replaces the text between each part's markers.
  `main` wires them; `cli.STAGES` gains `card`.
- Without `--sweep` only the definition is read. With it, the stage reads
  `preflight/stamp.json`, `datacheck/measurements.json` (judged again with
  `verification.criteria.judge`, as `verify` does), `converge/convergence.json`,
  each case's `provenance.json` and `run.json`, and `manifest.csv`.
- `--out` writes elsewhere (default: the definition's own file). `--check`
  writes nothing and exits 1 when the file on disk differs from the render:
  the drift test of a committed card.
- Exit codes as the other stages: 0 written or unchanged, 1 `--check` found
  a difference, 2 refused (no definition, a card without markers, a marker
  opened and not closed).
- Output is bytes, LF, with no timestamp of its own, no absolute path, no
  host or user name: dates and commits come from the records. Rendering twice
  gives the same bytes. An admitted dataset's definition is published
  (ADR-0074 clause 8), so the card is written as a public file from the
  start.

## 2. The template (flag-first)

Today each generated section holds one comment, `<!-- GENERATED from ... -->`,
which cannot delimit a part inside a section that the author also writes in
("Quantities of interest", "Resolution and horizon"). The template moves to
the start/end pair `CONTRIBUTING.md`'s admission list already uses:

    <!-- card:variables:start (generated by structbench-datagen card; do not edit by hand) -->
    ...
    <!-- card:variables:end -->

Everything outside a pair is the author's. A card still carrying the old
single comment is refused with one line naming the section and the pair to
put there; nothing is migrated silently, because the stage cannot know which
lines under an old comment the author wrote.

One section is added, **Survivor log**, because the data standard requires one
(ADR-0073 D14) and the template has no place for it. The sections and what
fills each:

| Section | Part | Read from |
|---|---|---|
| What it is · Model and why · Validation against experiments · Known limitations | author | — |
| Variables and splits | `variables` | `dataset.toml`: the box, the fixed constants, each split's kind, size, seed, and whether it is a probe or withheld |
| Stored data | `stored` | `[declaration]`; with a sweep, the fields the instrument found stored |
| Quantities of interest | `qoi` + author | `[qoi]` names, units, tolerances; with a sweep, the range of each over the converted cases |
| Survivor log | `survivors` | the plan and the run records: planned, generated, completed, each other status with its case ids, exported, converted, verified |
| Verification of the runs | `verification` | `datacheck/measurements.json`: verdict counts per row, the failing rows by case, the measured-only spreads, the accepted gaps with what they covered |
| Discretization uncertainty | `convergence` | `converge/convergence.json`: per quantity the observed order, the extrapolated error at the production level, the field errors per level |
| Resolution and horizon | `resolution` + author | the stamp: the production level, the increment key and factors with the changes measured, the frame interval with its interpolation error, the settling frame and the share of the horizon after it, the contact separation where named |
| Provenance and reproduction | `provenance` | the definition's three hashes, the stamp's, the StructBench versions and commits the cases were generated under, the solver release the run records name, the commands |

The three shipped examples' cards are rewritten on the new template and
rendered without a sweep; their author sections are drafted from the
examples' READMEs for the maintainer to edit.

## 3. Judgments the build rests on

1. **The scored horizon is an author line.** ADR-0071's note of 2026-09-27
   has the card declare it; it is the benchmark protocol's (ADR-0078), and
   `datagen` does not read a `benchmark.py` (ARCHITECTURE's layering; the
   reason `archive` takes `--seed-frames`). The generated part reports the
   stored horizon and the settling; the author states the scored horizon
   beside it.
2. **The card feeds the benchmark card by content, not by code.** Nothing
   depends on `datagen`. The generated parts carry the evidence the standard's
   items ask for under the standard's own names (`convergence_run`,
   `survivor_log`), so a benchmark author fills the compliance table from the
   card. `noise_floor` and `constitutive_sensitivity` have no producing stage:
   the survivor part ends with a line saying so. Generating a `BenchmarkCard`
   from these records is admission work and waits for the first dataset that
   needs it (CORRECTIONS 2026-09-21).
3. **A record for another definition is shown as such.** When the stamp's
   hashes are not the current definition's, the resolution part says so in
   its first line and still renders: the card is a report, the gate is
   `generate`'s. The same for a provenance whose hashes differ.
4. **A partial verification record is shown as partial.** `verify --split`
   replaces `datacheck/`, so the verification part states how many of the
   sweep's completed cases the record covers and names the splits it does
   not.
5. **Infeasible draws are not in any record today.** `sampling` filters them
   silently. The survivor part reports what the records hold; counting the
   draws `feasible()` rejected needs `plan_cases` to return them, which this
   plan adds (a count per split in the plan, written to `manifest.csv`'s
   sibling `plan.json`). *If the maintainer prefers no new record, the part
   says "not recorded" instead.*

## 4. Tests

`tests/datagen/test_datagen_card.py`, no solver: each renderer on a hand-built
record; an absent record renders its absence; author text outside the
markers survives two renders byte for byte; an old-template card is refused;
`--check` detects drift; no absolute path or host name in a render of the
end-to-end fixture (the stand-in sweep of `test_preflight_e2e`); the three
shipped cards equal their render (`--check`); the scaffold's card passes
`card` then `check`. `test_cli`'s stage list gains `card`.

## 5. Closing the thread

`docs/DATA_GENERATION.md` gains the stage's section and loses its "still
owes" header; the README Roadmap item is struck; the three example READMEs
and the CLI docstring name the stage; `CLAUDE.md`'s snapshot reads "ADR-0071
built"; this plan's row in `docs/plans/README.md`. No note is added to
ADR-0071: it carries six, and a build log is not a note
(`docs/decisions/README.md`, Notes).

## Not in this plan

A `BenchmarkCard` generated from datagen records; a card in the published
archive's layout; a second solver's records (the stage reads the neutral
records the stages already write); the noise-floor and
constitutive-sensitivity studies themselves.
